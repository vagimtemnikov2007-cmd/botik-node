# Botik Node

Telegram-бот на Node.js 22.9+ (рекомендуется 24 LTS), вдохновлённый [vladimirsnow/botik](https://github.com/vladimirsnow/botik).

## Запуск на Render

В Logs при запуске выводится `Media tool available` с версиями yt-dlp, FFmpeg и FFprobe. Если инструмент отсутствует, запуск останавливается с `Media tool unavailable`. При `Job failed` поле `details.stderr` содержит предупреждения и отладочный вывод yt-dlp (версии зависимостей, этап запроса, исходную ошибку); `details.stage` показывает `metadata` или `media_download`. Это фактический вывод загрузчика, а не предположение о блокировке сайта. Настроенные секреты и параметры URL скрываются. После изменения кода сделайте push и новый deploy; для обновления yt-dlp в Docker используйте сборку без кеша.

Создайте **Web Service**, подключите репозиторий проекта и выберите **Docker**. Dockerfile устанавливает Node.js, yt-dlp и FFmpeg. В Advanced задайте Health Check Path: `/healthz`.

В **Environment** добавьте:

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен от BotFather |
| `WEBHOOK_SECRET` | Случайная строка из 32–64 латинских букв и цифр |
| `CONCURRENCY` | `1` для небольшого сервера |

Адрес сервиса берётся автоматически из `RENDER_EXTERNAL_URL`, порт — из `PORT`. Render предоставляет эти переменные: [официальная документация](https://render.com/docs/environment-variables). Если нужен собственный адрес, задайте `WEBHOOK_URL=https://ваш-домен`; путь `/telegram` бот добавит сам.

Нажмите **Save and deploy**. Для запуска не нужны `.env`, файлы cookies с компьютера, база данных или постоянный диск. Секреты храните в Environment Render, а не в репозитории. Локальные переменные `YTDLP_PATH`, `FFMPEG_PATH`, `FFPROBE_PATH` и `COOKIES_FILE` больше не используются: инструменты находятся через системный `PATH`.

Бот временно сохраняет медиа в системной папке временных файлов, чтобы yt-dlp и FFmpeg могли скачать/обработать файл, а Telegram — получить его. После отправки, отмены или ошибки папка задачи удаляется. Очередь, кеш Telegram file_id и настройки качества находятся в памяти; перезапуск сбрасывает их. Это версия для одного экземпляра.

## Возможности

| Источник | Что получает пользователь |
| --- | --- |
| YouTube / Shorts | Видео, MP3 по команде `/audio` |
| X / Twitter | Видео, фото, смешанные альбомы и текст через FxTwitter; резервный путь yt-dlp для видео |
| Instagram | Reels и видеопосты; фото-карусели не реализованы |
| Pinterest / pin.it | Видео через yt-dlp, фото через OpenGraph страницы пина |
| TikTok | Видео; отдельная обработка фото-слайдшоу не реализована |
| Музыка | Первый результат поиска YouTube в MP3 с метаданными |

Отправьте ссылку, в том числе в подписи к фото или как скрытую ссылку. Можно отправить несколько ссылок в одном сообщении.

- `/quality` — качество 360/720/1080p.
- `/audio ссылка` — MP3 из видео.
- `/music исполнитель название` — поиск музыки.
- `/cancel` — отмена ваших задач в текущем чате.
- `/status` — состояние очереди и выбранное качество.
- `/id` — Telegram ID для ограничения доступа.
- `/help` — справка.

Для обработки обычных сообщений в группе отключите Privacy Mode через BotFather (`/setprivacy`) и повторно добавьте бота. В группе поиск музыки также работает через `@имя_бота исполнитель название`. В канале боту нужно право отправки сообщений; при заданном `ALLOWED_USERS` публикации каналов без пользовательского отправителя не обрабатываются.

По умолчанию: до 3 ссылок и 10 файлов за запрос, 30 задач в очереди, видео до 30 минут, таймаут загрузки 5 минут, файл до 49 МиБ. Крупные видео бот пытается сжать. Изображения свыше 9 МиБ отправляются документом. Все параметры перечислены в `.env.example` — это только образец настроек, файл не требуется для запуска.

## Cookies без внешнего файла

Если сайт требует авторизации, задайте необязательную секретную переменную `COOKIES_TEXT`: полное содержимое Netscape cookies, начиная с `# Netscape HTTP Cookie File`, с настоящими переносами строк. yt-dlp требует файловый интерфейс cookies, поэтому бот создаёт приватную временную копию только внутри папки задачи и удаляет её вместе с задачей. Не нужен постоянный файл cookies или путь к нему. При cookies личного аккаунта ограничьте доступ через `ALLOWED_USERS=123456789,987654321`.

Некоторые публикации и серверные IP могут блокироваться сайтами. Stories, трансляции и публикации без необходимого доступа не поддерживаются. Обновляйте Docker-образ для получения новой версии yt-dlp. Наличие адаптера не гарантирует доступность каждой ссылки.

## Другие способы запуска

Вне Render пустой `WEBHOOK_URL` включает polling. Передайте токен через окружение:

```bash
read -r -s -p "BOT_TOKEN: " BOT_TOKEN
export BOT_TOKEN
npm ci
npm run doctor
npm start
```

Понадобятся yt-dlp, FFmpeg и FFprobe в системном `PATH`. Можно использовать Docker: после задания окружения выполните `docker compose up -d --build`. Compose передаёт настройки в контейнер через environment. Файл `.env` не требуется.

Для локальной разработки при желании можно явно загрузить собственный `.env`: `node --env-file=.env src/index.js`. Команды npm автоматически его не читают.

## Проверки

`npm run check` — проверка синтаксиса и автоматические тесты очереди, отмены, обработки ссылок, конфигурации Render, удаления временных cookies, подменённого Telegram API и реального сжатия через FFmpeg.

`npm run doctor` — проверка программ и окружения без отправки сообщений в Telegram.

`npm run smoke -- https://ссылка_на_публикацию` — настоящее скачивание без Telegram-токена, вывод типов и размеров файлов, затем удаление временных файлов. Можно передать несколько ссылок. yt-dlp и FFmpeg должны находиться в `PATH`.

[VERIFICATION.md](VERIFICATION.md) содержит результаты прежних реальных загрузок. Проверка деплоя на Render выполняется отдельно после подключения сервиса.
